# Análisis y seguimiento del codelab

Fuente única: https://epanchanaf.github.io/tinyprice-codelab/ (consultada el 22 de octubre de 2026). Se leyeron íntegramente sus 16 artículos antes de modificar la aplicación. La navegación coloca TinyFish antes de Android, aunque los artículos del HTML tienen otro orden; este documento sigue la navegación.

La sección final enlaza `reference/README.md` y una instantánea completa de Android y Supabase. Sus instrucciones autorizan copiar esos archivos al proyecto creado con Empty Activity. Se utiliza esa referencia, sin rediseñar la aplicación ni añadir dependencias funcionales.

## Observaciones iniciales

- Ya existía `IATinyFish/` con el commit `37061d4`, que registra su creación mediante Android CLI y la plantilla oficial Empty Activity. No se afirma que se haya usado el asistente gráfico de Android Studio.
- Se conserva ese historial y no se modifica el segundo proyecto de plantilla situado en la carpeta superior.
- El teléfono conectado utiliza API 35, compatible con minSdk 23. Los SDK 37.0 y 37.2 están instalados.
- Se comprobó disponibilidad HTTP 200 de AGP 9.4.1, Gradle 9.6.0 y Compose BOM 2026.02.01 en sus distribuidores oficiales.
- El registro y verificación de TinyFish y Supabase permanecen pendientes mientras se desarrolla la parte independiente. No se simulan cuentas ni resultados remotos.
- Gemini CLI es opcional; su actividad interactiva no es un requisito de ejecución de TinyPrice.

Los resultados ejecutados se documentarán en `VERIFICACION.md`.

## Cierre y diferencias comprobadas

- La referencia completa del repositorio de demostración incluye una tercera oferta, Tech Mart, además de las dos del fragmento explicativo. Se conserva la referencia completa, incluidos sus textos originales. La descripción temprana del commit del modelo menciona solo las dos primeras; el código de ese commit ya contiene las tres.
- La función enlazada en `reference/` omite el timeout del bloque del paso 12. Se utiliza íntegramente el bloque del paso 12, que sí contiene AbortController y el límite de 15 segundos. No se añade procesamiento ajeno al tutorial.
- Las versiones originales se resolvieron y compilaron inicialmente. Al abrir el proyecto se comprobó que Android Studio Quail 3 rechaza AGP 9.4.1 y admite la rama 9.3; se ajusta únicamente AGP a 9.3.3, manteniendo Gradle 9.6.0 y SDK 37, de acuerdo con la excepción de compatibilidad autorizada por el usuario. Quedan 19 archivos Android idénticos a la referencia; los cuatro archivos con diferencias son el catálogo de versiones, gradle.properties, DealsApp.kt y DealsAppTest.kt.
- La cabecera se superponía a la barra del sistema en el teléfono. Se aplicó `statusBarsPadding()` a búsqueda y detalle, manteniendo el diseño original.
- Se excluyeron los glifos decorativos del árbol accesible conforme al paso 9. Los textos de la portada usan `onPrimary`, ya definido por el tema, para conservar contraste en oscuro; no se modificó la paleta. Se verificaron portada y resultados con fuente ampliada a 1.3 y se restauró el tamaño original.
- La prueba con ComponentActivity genérica no completó el arranque en el teléfono. Se usa `createAndroidComposeRule<MainActivity>()`, manteniendo las mismas dos aserciones; el XML final confirma una prueba aprobada.
- El usuario autorizó expresamente utilizar su cuenta existente de Supabase, iniciada con GitHub. Por eso no se declara realizado el registro por correo del paso 10.
- Android CLI 1.0.16625370 exige `android skills add android-cli --project=.`; la variante sin nombre respondió que faltaba especificar la skill. Su paquete oficial actual instaló SKILL.md, pero no produjo `references/` ni `skills-lock.json`. No se fabricaron esos archivos ni se atribuyó al instalador una salida que no generó. Gemini CLI no estaba instalado y su actividad opcional no se ejecutó.
- Se creó el proyecto Supabase real, se enlazó la CLI y se desplegó la función. Se rotó la clave y se verificó nuevamente HTTP 200. El recorrido Android → Supabase → TinyFish se comprobó en el teléfono.
- El límite didáctico devolvió 429 en la comprobación aislada de una instancia; no se reprodujo en 26 solicitudes inválidas al despliegue. Esto confirma que no debe tratarse como un límite compartido o durable.

El estado final de cada comprobación está en [VERIFICACION.md](VERIFICACION.md).
